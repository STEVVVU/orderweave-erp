# Orderweave development

This checkout is the Tryton 8.0.12 monorepo pinned at `05c8430b9f479cf17d3fd9113cc60db7a94663bf`. Preserve upstream source, licenses, and history. Keep Orderweave changes in its own conventional Tryton module under `modules/orderweave` and its own verification tools under `.agents/skills/verify-orderweave/`.

Use the repository's Python 3.11 environment at `.venv`. Bootstrap the pinned server, Proteus, and module dependency closure with `python scripts/bootstrap_orderweave.py`; never install dependencies globally. The bootstrap builds vendored packages from this exact checkout and installs third-party dependencies from `requirements-orderweave.lock.txt`. For focused module checks, run `$env:TZ='UTC'; .\.venv\Scripts\python.exe -m unittest trytond.modules.orderweave.tests.test_module`. For the real authenticated RPC path, run `.\.venv\Scripts\python.exe scripts/verify_orderweave.py run`; this covers Launch, Doctor, Drive, Evidence, and Cleanup and retains evidence in `.audit/evidence/`. Treat SQLite as a single-writer demo database, not a production concurrency guarantee.

Follow nearby Tryton conventions: register models and wizards in `__init__.py`, list dependencies and XML in `tryton.cfg`, keep models in focused Python files, and put ORM tests in `tests/test_module.py` using `ModuleTestCase` and `with_transaction`. Use `Decimal` for money and quantities where exact arithmetic matters. Keep changes compatible with the pinned 8.0 API and run checks from this checkout. GitHub Actions runs these same bootstrap, focused tests, and RPC verification steps only for `orderweave` branch activity; it also builds Sao with the locked dependency tree. Do not run a browser driver outside CUA.
